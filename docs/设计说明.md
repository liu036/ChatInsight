# 设计说明 · ChatInsight

> 本文档补充 README 之外的设计细节，供代码走读与面试讨论使用。

## 1. 输入格式约定

支持三种行格式，解析器（`core/parser.py`）按优先级识别：

```text
=== 会话标题 ===                        # 会话分隔（可省略，靠时间跳变兜底）
[2026-10-20 09:12] 王强：内容           # 带时间戳
王强：内容                              # 无时间戳（继承上一条）
```

无法识别的行（公告、图片说明等）直接忽略。宁可漏一条，也不要把非消息当消息——
否则会污染 LLM 上下文，抽取结果不可信。

## 2. 分组策略

同一会话内，相邻消息时间差超过 30 分钟（`CHATINSIGHT_SESSION_GAP_MINUTES`）即切分新组。
分组同时承担两个职责：

1. **上下文边界**：控制单次 LLM 输入长度；
2. **并发单元**：一组一次调用，N 组即可填满线程池。

每组渲染时附带上一组末尾 5 条消息（`CHATINSIGHT_CONTEXT_TAIL`），
并在 prompt 中明确"仅用于理解语境，请勿抽取"。

## 3. 归一化状态机

```text
todo ──► doing ──► done     （只进不退）
```

合并键 = (执行人, 规范化任务名)。规范化 = 去标点 → 去首动词语气词 → 同义词映射。
同义词表 `SYNONYMS` 按长度从长到短替换，避免短键误伤长任务名。

## 4. 失败模式清单

| 失败 | 表现 | 处理 |
|---|---|---|
| LLM 超时/网络错误 | 客户端异常 | 标记失败组，其他组继续；统计展示失败数 |
| 输出不是 JSON | 解析失败 | 带修复提示重试（默认 2 次），仍失败标记 parse_error |
| JSON 结构不对 | 缺 items 键 | 同上，走降级链 |
| 单条字段缺失 | Pydantic 校验失败 | 丢弃该条，保留同组其他条目 |
| 消息无时间 | msg_time 为 None | 按 raw_text 匹配回填；匹配不到则排序置顶 |

## 5. Mock 模式定位

Mock 规则引擎（`core/mock_engine.py`）用 3 条正则覆盖示例数据的典型句式，
它的价值不是"聪明"，而是**确定性和零依赖**：

- 无 API Key 的面试/演示现场；
- pytest 不发起网络调用；
- 与真实 LLM 输出同构（同样的 JSON schema），便于对比讲解。
